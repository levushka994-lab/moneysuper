# План: локальная модель, которая отвечает «нормально»

Задача: чтобы AutoR мог отвечать покупателям **без DeepSeek** — силами домашнего сервера `eta`
(Intel i7-10750H, 6 ядер / 12 потоков, 15 GB RAM, GPU нет, 831 GB диска свободно).

## Честная вводная

`mnn-pocket-0.3b`, который сейчас крутится на машине разработчика, для ответов покупателям не годится:
0.3B параметров не удерживает ни факты каталога, ни тон. Дообучение 0.3B не спасёт — у модели просто
нет ёмкости. Рабочий диапазон для CPU-инференса на 12 потоках — **1.5B…3B** в квантовании Q4_K_M:
≈2 GB RAM, 8–15 ток/с, ответ в 40 токенов за 3–5 с. Это и есть целевой размер.

Три вещи дают «нормально» в такой задаче, и все три нужны:

1. **Факты** — каталог, цены, сроки подставляются в промпт (уже сделано: `features.js`, `fillMacros`).
   Дообучение фактам не учит — оно учит *формату поведения*: коротко, по делу, без выдумок, эскалация.
2. **Стиль и правила** — LoRA-SFT на 2–4 тыс. диалогов, дистиллированных из DeepSeek.
3. **Контроль выдумок** — проверка чисел в ответе против каталога на бэкенде (repair/эскалация).

## Этапы

### 0. Стенд на eta (0.5 дня)
- `uv` + Python 3.12 (системный 3.14 не годится для torch/bitsandbytes).
- `llama.cpp` из исходников (`cmake -DGGML_NATIVE=ON`), `llama-server` как `autor-llm.service` на `127.0.0.1:8081`.
- Caddy на eta: `handle /api/local-chat* { reverse_proxy 127.0.0.1:8081 }` — сайт ходит на относительный путь,
  поэтому одна и та же сборка работает и на VPS (DeepSeek), и на eta (локальная модель).
- В `features.js` заменить жёсткий `http://127.0.0.1:8080/v1/chat/completions` на относительный `/api/local-chat/v1/chat/completions`.

### 1. Данные (1–2 дня)
- `make_dataset.py`: из `catalog.json` (7 позиций + профиль магазина) генерируются пары «вопрос → ответ».
  Учитель — DeepSeek через уже существующий `/api/chat`; жёсткий системный промпт + 6 типов интентов:
  наличие, цена за м²/за единицу с расчётом, сроки/замер, доставка, скидка (не давать цифру), вне каталога (эскалация).
- Мультитёрн: 1–3 реплики, чтобы модель видела контекст.
- Объём: 2500–4000 пар после фильтра (judge ≥4/5, длина ≤ 45 слов, числа совпадают с каталогом).
- Негативы: вопросы не по теме, провокации, просьба скидку «здесь и сейчас», выдуманный товар.
- Хранить JSONL в chat-формате (`messages`), сплит 90/5/5.

### 2. Обучение (2–4 часа на арендной GPU)
- База: `Qwen2.5-1.5B-Instruct` (дефолт) или `Qwen2.5-3B-Instruct` (если хватит терпения на инференс).
- QLoRA 4-bit, r=16, alpha=32, lr 1e-4, 2–3 эпохи, seq 1024 → на RTX 4090 это 30–60 минут, ~150–300 ₽ аренды.
- `train_qlora.py` в этой папке, конфиг — аргументами.
- CPU-путь (без аренды): `train_cpu_llamacpp.sh` — `llama-finetune` на квантованной базе, LoRA.
  Реалистично 4–8 часов на эпоху 1.5B; гонять ночью через systemd-таймер. Качество ниже, чем QLoRA,
  но для проверки гипотезы хватает.
- Слияние: LoRA → HF → `convert_hf_to_gguf.py` → `llama-quantize Q4_K_M`.

### 3. Оценка (полдня, но постоянно)
- `eval.py` гоняет `golden.jsonl` (100–150 заготовок, начало из 40 кейсов в этой папке) против любого
  OpenAI-совместимого эндпоинта и считает автоматические метрики:
  - `fact` — числа в ответе совпадают с каталогом (цена, остаток, срок);
  - `halluc` — в ответе есть число, которого нет в фактах;
  - `len` — слов ≤ 45;
  - `escalate` — на вопрос вне каталога/со спорной скидкой диалог передан менеджеру;
  - `judge` — оценка DeepSeek 1–5 по рубрике «полезно, честно, коротко».
- Ворота приёмки: `fact ≥ 95%`, `halluc ≤ 1%`, `escalate ≥ 90%`, `judge ≥ 4.0`, p95 ≤ 4 с на eta.
- Для сравнения: DeepSeek Flash как верхняя граница, 0.3B как нижняя.

### 4. Подключение (полдня)
- `source: local` в настройках уже есть; после этапа 0 он указывает на `/api/local-chat`.
- Fallback: если локальная модель не ответила за 6 с или ответ не прошёл валидацию чисел — уходим в `/api/chat`
  (или честно передаём менеджеру).
- Публичный `autor.site-port.ru`: `/api/local-chat` проксируется на VPS в тот же тоннель (второй `-R 127.0.0.1:8091:127.0.0.1:8081`).

## Риски и как их гасим

| Риск | Гасим |
|---|---|
| 1.5B всё равно выдумывает цену | проверка чисел на бэкенде + ответ по шаблону с фактами |
| CPU слишком медленный | 1.5B Q4_K_M, `-np 2`, стриминг, потолок 40 токенов |
| Датасет однообразный, модель повторяет фразы | больше формулировок в генерации, temperature 0.8 у учителя, дедуп по n-граммам |
| Юридически: обещания скидок/гарантий | в промпте и в датасете — только то, что есть в каталоге, иначе эскалация |

## Что считаем победой

Модель на eta в 1.5–3B, которая на 100 вопросах из `golden.jsonl` даёт ≥95% верных цифр,
не выдумывает наличие и скидки, укладывается в 45 слов и 4 секунды — и при этом не зависит от внешнего API.
