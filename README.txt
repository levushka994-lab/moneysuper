AutoR — сайт на сервере и бэкапы на компьютере
==============================================

В этой папке:
  index.html               — каркас страницы сайта AutoR
  assets\css\              — стили сайта (foundation, components, pages, responsive…)
  assets\js\               — скрипты сайта (seed, charts, app, billing, cabinet, features)
  deploy.ps1               — выложить или обновить сайт на сервере
  server-setup.sh          — установщик, deploy.ps1 сам отправит его на сервер
  sync-deploy.sh           — автовыкладка: сервер сам забирает свежий сайт с GitHub
  install-sync.sh          — поставить автовыкладку на сервер (один раз, от root)
  backup.ps1               — скачать бэкап с сервера на этот компьютер
  install-backup-task.ps1  — бэкап каждый день по расписанию
  README.txt               — эта инструкция

Структура сайта (папка assets):

  index.html               — каркас страницы: разметка, иконки, подключение файлов
  assets\css\foundation.css — шрифты, цвета, сброс стилей, каркас
  assets\css\components.css — кнопки, карточки, таблицы, модальные окна
  assets\css\pages\        — стили страниц: dashboard, chats, catalog, rules,
                              analytics, analysis, settings
  assets\css\responsive.css — адаптив для планшета и телефона
  assets\css\theme.css      — тема «Пульт автопилота»
  assets\css\access.css     — экран входа, тарифы, замки на функциях
  assets\css\cabinet.css    — чистый кабинет и пример магазина
  assets\css\features.css   — доработки страниц
  assets\js\seed.js         — данные магазина, товаров, чатов и сценариев
  assets\js\charts.js       — графики
  assets\js\app.js          — кабинет: состояние, роутер, страницы
  assets\js\billing.js      — доступ, промокоды, тарифы
  assets\js\cabinet.js      — чистый кабинет и «Показать пример магазина»
  assets\js\features.js     — доработки страниц

  Правило: разметка — в index.html, внешний вид — в assets\css, поведение — в assets\js.

Сервер по умолчанию: root@site-port.ru (домен site-port.ru).
Сервер принадлежит другу — предупредите его перед установкой.


1. ПОДГОТОВКА
-------------
Распакуйте архив в папку C:\AutoR (путь лучше латиницей, без пробелов).
Откройте PowerShell (Win+X → Терминал / Windows PowerShell) и перейдите в папку:

    cd C:\AutoR


2. ВЫЛОЖИТЬ САЙТ
----------------
    powershell -ExecutionPolicy Bypass -File .\deploy.ps1

- Пароль сервера спросит 2 раза (если вход не по ключу). Символы пароля не видны — это нормально.
- Скрипт покажет, что нашёл на сервере, и спросит «Продолжить? [y/N]» — нажмите y и Enter.
- Он ставит nginx (если его нет), кладёт сайт в /var/www/autor, добавляет отдельный
  конфиг autor.conf и выпускает бесплатный сертификат HTTPS. Другие сайты не трогает.
- В конце откройте https://site-port.ru

Если домен другой:  powershell -ExecutionPolicy Bypass -File .\deploy.ps1 -Domain другой-домен.ru -Server root@другой-домен.ru


3. ЕСЛИ СКРИПТ ОСТАНОВИЛСЯ
--------------------------
Он специально останавливается и НИЧЕГО не меняет, если видит, что может сломать чужое:
- «Порт 80 занимает не nginx» — на сервере уже работает другой сайт или панель;
- «Домен уже настроен в другом конфиге nginx» — на этом домене уже есть сайт;
- «Конфигурация nginx на сервере уже с ошибкой» — nginx был сломан до нас.
Пришлите мне весь вывод — разберёмся.

Если пишет «По адресу ... сейчас открывается сайт «...»» — значит, на домене уже что-то есть,
и после установки там будет AutoR. Если это сайт друга — ответьте n и спросите его.


4. БЭКАП ВРУЧНУЮ
----------------
    powershell -ExecutionPolicy Bypass -File .\backup.ps1

Архивы складываются в C:\Users\<ваше имя>\AutoR-backups, имя вида autor-2026-11-07_21-00.tar.gz.
Хранятся последние 30, старые удаляются сами. Журнал — backup.log в той же папке.
В архиве: файлы сайта и его настройка nginx.


5. БЭКАП КАЖДЫЙ ДЕНЬ
--------------------
Нужен вход по ключу (раздел 6) — по расписанию пароль вводить некому.

    powershell -ExecutionPolicy Bypass -File .\install-backup-task.ps1

По умолчанию — каждый день в 21:00. Другое время:  ... install-backup-task.ps1 -Time 09:30
Если компьютер был выключен — бэкап сделается при следующем включении.
Если пишет «Отказано в доступе» — запустите PowerShell от имени администратора.

Сделать бэкап прямо сейчас:   Start-ScheduledTask -TaskName 'AutoR backup'
Убрать расписание:            Unregister-ScheduledTask -TaskName 'AutoR backup' -Confirm:$false


6. ВХОД ПО КЛЮЧУ (без пароля)
-----------------------------
На компьютере (PowerShell), Enter три раза:

    ssh-keygen -t ed25519 -C "lev"

Отправить ключ на сервер (один раз спросит пароль):

    type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@site-port.ru "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"

Проверка — должно пустить без пароля:

    ssh root@site-port.ru

Файл id_ed25519 (без .pub) — ваш закрытый ключ, никому его не отправляйте.


7. ОБНОВИТЬ САЙТ
----------------
Положите новый index.html в C:\AutoR вместо старого и снова запустите deploy.ps1.
Прошлая версия на сервере сохранится как /var/www/autor/index.prev.html.


8. ВОССТАНОВИТЬ ИЗ БЭКАПА
-------------------------
Распакуйте нужный архив (в PowerShell, в папке с бэкапами):

    tar -xzf autor-2026-11-07_21-00.tar.gz

Файл сайта будет в var\www\autor\index.html — скопируйте его в C:\AutoR вместо index.html
и запустите deploy.ps1. Настройка nginx (autor.conf) лежит в etc\nginx\... — она нужна,
только если сервер переустановили с нуля; тогда deploy.ps1 создаст её заново сам.


9. ВАЖНО ЗНАТЬ
--------------
- Режим разработчика в этой сборке вырезан полностью: секретное название ничего не включает.
- Кабинеты покупателей (товары, чаты, настройки) хранятся в браузере каждого покупателя —
  на сервере только сам сайт. Поэтому бэкап — это копия сайта и его настроек.
- Промокоды проверяются в браузере. Файл с кодами храните у себя, на сервер его не кладите.
- Пароль root, который пересылался в переписке, смените на сервере командой  passwd


10. АВТОВЫКЛАДКА — САЙТ ОБНОВЛЯЕТСЯ САМ
--------------------------------------
На сервере стоит таймер: раз в минуту он проверяет ветку main на GitHub и, если
файлы сайта изменились, сам выкладывает новую версию — всю папку сайта целиком
(index.html + assets). Прошлый index.html сохраняется как /var/www/autor/index.prev.html.

Как пользоваться (на этом компьютере, в папке с файлами):

    git add -A
    git commit -m "что изменили"
    git push

Через минуту изменения на https://site-port.ru. Больше ничего запускать не нужно.

Проверить, что сервер подхватил (по SSH):

    systemctl start autor-sync.service     — прогнать проверку прямо сейчас
    tail -20 /var/log/autor-sync.log       — что сервер делал
    systemctl list-timers autor-sync.timer — когда следующая проверка

Отключить автовыкладку:   systemctl disable --now autor-sync.timer
Включить снова:           systemctl enable --now autor-sync.timer

Если на сервере автовыкладки ещё нет (новый сервер), поставьте один раз от root:

    bash install-sync.sh

Автовыкладка обновляет только index.html. Если менялся server-setup.sh (настройка nginx),
в логе появится предупреждение — тогда запустите deploy.ps1 вручную.
